## 1. 現況問題（已量測）

| 問題 | 原因 | 量測 |
|---|---|---|
| 音訊片段交接處斷音 | 每個片段是獨立的 audio 元素，`play()` 起播要時間 | 70 到 160 ms 空白 |
| 切點畫面沒準備好時聲音也停 | 時鐘在 `isWaiting()` 時整個暫停，`hold()` 連聲音一起停 | 最長可停 4 秒（WAIT_LIMIT_MS） |
| 影片元素的 seek、緩衝會打斷原聲 | 原聲直接從 video 元素出來 | 每次校正 seek 都會斷一下 |
| 時鐘以 performance.now 計算 | 與音效卡時鐘不同源 | 音效卡快 196 到 263 ppm（每分鐘差 13 到 16 ms） |
| 畫面對齊「排程時間」而非「實際出聲時間」 | 沒扣輸出管線延遲 | 固定差 53.2 ms（約 1.6 格） |
| 音訊環境取樣率跟著裝置 | `new AudioContext()` 沒指定取樣率 | 裝置是 44.1k 時每個來源各自重取樣 |

## 4. 架構

```
來源檔（影片原聲、音訊片段、上層片段原聲）
  → 伺服器音訊代理檔（WAV s16le 立體聲 48k，混音方式與輸出相同）
  → /file Range 分段讀取（分離人聲 stems 已是 WAV f32，直接讀）
  → PCM 區塊快取（5 秒一塊，上限 256 MB，最久沒用的先丟）
  → 排程器：AudioBufferSourceNode 依樣本起訖排好，一律明確 stop()
  → 每片段增益（音量、關鍵幀、淡入淡出、閃避，沿用現有計算）
  → 音軌匯流 → 主匯流（音量表、獨奏、監聽模式照舊）→ 喇叭

時鐘：主匯流「實際出聲的時間」（getOutputTimestamp 換算）→ 畫面跟著這個時間畫
畫面：影片元素一律靜音，只負責畫面；落後就跳格或微調速度追上，不再讓聲音等畫面
```

### 不做（理由）

- **改成獨立 APP**：桌面版用 WebView2，與瀏覽器同一個引擎，問題相同。
- **伺服器即時整段混音**：每次改剪輯都要重算，剪輯中聽不到即時結果。
- **WebCodecs 自己解碼畫面**：成本大，現在的瓶頸在聲音，不在畫面。
