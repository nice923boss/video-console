# Spike：SB-14 劇本與分鏡雙向同步

- **日期**：2026-10-25
- **負責人**：Claude（人工抽檢：待黃政文驗收）
- **目標項目**：改進清單 SB-14（[改進進度.md](改進進度.md) 第 15 批）
- **狀態**：✅ 通過（程式層面與瀏覽器介面已驗證，見 GAPS 第 15 批驗收紀錄）；限制見 GAPS #369

## 1. 要驗證的假設

1. 分鏡可以轉成一份純文字劇本，再從這份文字讀回每個欄位，不會讀錯欄位。
2. 改了文字只寫回改過的欄位，同一時間在分鏡上改的其他欄位不會被蓋掉。
3. 在文字裡加新段落能變成新鏡頭，片長改變時其他軌道照「連動」規則跟著移。

## 2. 做法（為什麼不存一份劇本）

專案不另存劇本。每次打開都從鏡頭即時產生文字，所以「改分鏡 → 劇本跟著變」不用另外同步。
「改劇本 → 回寫分鏡」用三方比對：同時解析「打開時的文字」和「改過的文字」，只有兩者不同的欄位才寫回，
寫回的是「目前」的鏡頭。這樣避開了「解析不完全可逆」的問題：沒改的欄位就算讀回來有細微差異，也不會被寫入。

格式：

```
#3 屋頂賞月
描述：夜晚的屋頂，小黑貓背對鏡頭
  續行縮排兩格
動作：（有內容才列）
運鏡：（有內容才列）
字幕：第一句
字幕：第二句
片長：4
備註：（有內容才列）
```

## 3. 成功標準（Claude 自訂）

```
- 條件 1：兩個真實專案「轉文字再讀回」，欄位不一致 0 個
- 條件 2：沒改任何字直接套用，產生 0 個修改
- 條件 3：改描述時，同時在分鏡改的運鏡保留
- 條件 4：插入新段落、改片長後，後面的鏡頭、音軌、字幕依連動規則位移，數字對得上
```

## 4. 結果

| 測試 | 結果 |
|---|---|
| p_7ijfziw642（14 鏡）轉文字再讀回 | 98 個欄位，不一致 0 |
| p_vjj5ej469k（4 鏡）轉文字再讀回 | 28 個欄位，不一致 0 |
| 兩個專案沒改字直接套用 | 0 個修改 |
| 人造邊界案例（多行描述、空行、像標籤的內容、`#` 開頭的行、多句字幕、換行字幕） | 28 個欄位，不一致 2 |
| 改 #2 描述，同時在分鏡改 #2 運鏡 | 描述寫入，運鏡保留 |
| #1 片長 7.4 → 7，#3 後插入 3 秒新鏡頭（連動開） | #1 之後的音軌與字幕 -0.4 秒；插入點之後 +2.6 秒（-0.4 再 +3），新字幕 20.3～23.3 秒 |
| #1 加兩句字幕 | 0～3.7、3.7～7.4 秒，平分鏡頭時間 |

邊界案例的 2 個不一致：

1. 欄位開頭的空白（`  前置空白` 讀回 `前置空白`）
2. 欄位結尾的換行（`結尾空行\n` 讀回 `結尾空行`）

這兩種只在使用者改了那個欄位時才會被寫回（變成去掉空白的版本），不影響沒改的欄位。

## 5. 限制

- 兩個真實專案的字幕都沒有綁定鏡頭（36 句、4 句都是自由字幕），所以真實素材上的字幕同步只測了「新增」，「修改、刪除」只在人造案例和自動測試驗過。
- 文字永遠不會刪除或重排鏡頭：刪掉整段只代表「不改這個鏡頭」。要刪鏡頭或排序請在分鏡頁操作。
- 只顯示綁定在鏡頭上的字幕；未綁定的自由字幕不在劇本裡。
- 同一個欄位兩邊都改時，以劇本為準。
- 欄位開頭空白、結尾換行會被去掉（見上）。
