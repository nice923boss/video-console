# Spike：CP-13 字幕逐字高亮，配音能不能拿到逐字時間

- **日期**：2026-10-25
- **負責人**：Claude（逐字試聽抽檢：黃政文，2026-10-25 完成）
- **花費時間**：未精確計時，在同一個工作階段內完成
- **目標項目**：改進清單 CP-13（[改進進度.md](改進進度.md) 第 15 批）
- **狀態**：✅ 通過

## 1. 要驗證的假設

1. VoAI（雲端）或 Audio8Voice（本機）合成配音時，會一併回傳每個字的開始時間。
2. 如果不會，能不能在合成後只用「配音檔＋已知台詞」估出每個字的開始時間，誤差小到逐字變色看起來對得上。這個方法不能依賴語音模型或顯示卡。

## 2. 成功標準

標準由 Claude 自訂，黃政文沒有指定。標準是寫報告時才寫成文字，不算嚴格的事先訂定。

訂 100 ms 的原因：這批 VoAI 配音平均每個音節約 195 ms（14 段的中位數，範圍 172～212 ms），所以 100 ms 大約是半個字。

```
通過條件：
- 條件 1：查明兩個配音引擎回不回傳逐字時間，並附上文件或程式碼證據
- 條件 2：用有標準答案的語音（Windows 內建 zh-TW 語音的逐詞事件）測
    - 字的開始時間誤差在 100 ms 以內的比例 ≥ 90%
    - 最大誤差 ≤ 200 ms
- 條件 3：用真實 VoAI 配音測
    - 每段配音第 2 句起的句首，和專案字幕開始時間相差 150 ms 以內的比例 ≥ 90%
    - 最大誤差 ≤ 250 ms
- 條件 4：真實 VoAI 配音逐字試聽，變色比聲音早或晚超過約一個字的字 ≤ 10%
```

## 4. 測試樣本

**A. Windows 語音（有標準答案）**

- 內容：`tools/spike-cp13/lines.txt` 的 11 句口播台詞，含中文數字、「AI」、「60 秒」、問句與驚嘆句。
- 語速：正常語速（Rate 0）與較快語速（Rate 3）各念一次，每種語速 121 個詞的開頭。
- 標準答案：語音引擎的 SpeakProgress 事件，給出每個詞的文字位置與音訊位置。量過事件位置到實際出聲的延遲，中位數 0 ms。

**B. 真實 VoAI 配音（沒有逐字標準答案）**

- 來源：專案「Video Console 介紹（黑貓）」（p_7ijfziw642）。
- L01～L14 共 14 段：24 kHz、單聲道、16-bit，合計 80.3 秒，每段含 2～4 句字幕。另有 3 段 `Mosa_文澤_開心-*.wav`，各是單句網頁版匯出。
- 24 kHz 和 VoAI 輸出的取樣率上限相符，推定是 VoAI 產生，但沒有確認。
- 句首的參考值是專案既有的字幕開始時間。這些時間在 spike 之前就有了，製作方式不明。
- 台詞含「Video Console」「P5.js」這類中英混合詞。

## 5. 執行紀錄

### 5.1 條件 1：引擎回不回傳時間

**VoAI：不回傳**（證據等級 B，官方文件）

- 官方 swagger（`https://connect.voai.ai`，「voai.ai VoiceAPI v1」）列出 5 個介面。
- 3 個合成介面（`/TTS/Speech`、`/TTS/generate-voice`、`/TTS/generate-dialogue`）成功時只回 `audio/wav`、`audio/mpeg`、`audio/pcm`。
- 文字轉語音說明頁寫明，音檔以外只附 `x-used-quota`、`x-sample-rate`、`x-bit-depth`、`x-channels` 四個 header。
- 在 swagger 全文搜尋 timestamp、align、phoneme、viseme、word、duration、boundary，都找到 0 筆。

**Audio8Voice：我方用到的介面不回傳**（證據來自本專案程式碼）

- `app/vc/voice.py` 的 `synthesize()` 呼叫 `POST /synthesize`，回應就是整個 WAV（檢查開頭是 `RIFF`）。
- Audio8Voice 是作者另一個程式，不在這個儲存庫，這台電腦也沒有安裝，所以它其他介面沒有查到。
- 它雖然有載入 Whisper，但依 README 的說明，Whisper 只用來轉錄參考音，不轉錄合成結果。

**VoAI 金鑰**

- `data/secrets.json` 的金鑰用 DPAPI 加密，綁在另一個 Windows 帳號，這台電腦解不開。
- 因此這次沒有呼叫 VoAI，沒有花任何點數，改用專案裡既有的 VoAI 音檔。

### 5.2 估算方法（不用語音模型）

1. 每 10 ms 算一次音量（20 ms 窗）。比最大音量低 30 dB 以內算有聲，連續 100 ms 以上無聲算停頓。
2. 依標點把台詞切成短句，按字數比例猜每個標點在音檔裡的位置。
3. 用動態規劃把標點依序配到停頓：停頓越長、離猜測位置越近，越優先配對。沒配到停頓的標點，改放在猜測位置前後 300 ms 內最安靜的地方。
4. 短句裡的每個字依音節數分配有聲的時間：
    - 數字照中文念法算音節，例如「60」算 2 個。
    - 3 個字母以內，或全大寫 5 個字母以內的英文，逐個字母念。
    - 其他英文依母音組估音節數。
    - 「P5.js」裡的點會念出來，算 1 個音節。
5. 「吸附」：除了每個短句的第一個字，其他字的起點移到前後 50 ms 內最安靜的那一格，因為字與字的交界音量會掉下來。

表格中的模式：「平均」是整句平均分配，不看停頓；「分句」是第 1～4 步；「分句＋吸附」是第 1～5 步。

### 5.3 條件 2：Windows 語音（121 個詞開頭，比最大音量低 30 dB 內算有聲）

| 語速 | 模式 | 中位數 | p90 | 最大 | 100 ms 內 | 150 ms 內 |
|---|---|---|---|---|---|---|
| 正常 | 平均 | 68 ms | 206 ms | 288 ms | 64% | 81% |
| 正常 | 分句 | 48 ms | 102 ms | 151 ms | 89% | 99% |
| 正常 | 分句＋吸附 | 23 ms | 94 ms | 191 ms | 91% | 98% |
| 較快 | 平均 | 51 ms | 146 ms | 203 ms | 78% | 91% |
| 較快 | 分句 | 30 ms | 62 ms | 87 ms | 100% | 100% |
| 較快 | 分句＋吸附 | 15 ms | 50 ms | 87 ms | 100% | 100% |

改成 40 dB 時 Windows 語音更準（正常語速、分句＋吸附：中位數 21 ms、最大 127 ms、100 ms 內 96%），但 VoAI 會變差，見 5.4。

### 5.4 條件 3：真實 VoAI 配音（14 段，第 2 句起共 22 個句首）

| 有聲門檻 | 模式 | 中位數 | p90 | 最大 | 150 ms 內 | 平均偏差 |
|---|---|---|---|---|---|---|
| 30 dB | 平均 | 429 ms | 1014 ms | 1044 ms | 23% | 早 163 ms |
| 30 dB | 分句 | 51 ms | 127 ms | 170 ms | 91% | 晚 7 ms |
| 40 dB | 分句 | 85 ms | 170 ms | 677 ms | 77% | 早 63 ms |

- 句首只看「分句」：「吸附」不移動短句的第一個字，所以兩種模式在句首完全相同。
- 40 dB 比較差的原因：VoAI 句間的換氣聲約比峰值低 30～45 dB，門檻設 40 dB 時會把換氣當成說話，停頓被切斷。
- 每段第 1 句不列入：參考值是片段的起點，不是開口的時間。實測每段開頭都有約 200～300 ms 的換氣（約比峰值低 33 dB），30 dB 門檻會正確跳過。
- 誤差最大的 3 句：L12 第 2 句晚 170 ms、L08 第 2 句早 150 ms、L02 第 2 句早 130 ms。這些句子前的停頓又短又輕，L02 的參考時間本身也可能偏晚。

### 5.5 條件 4：逐字試聽

2026-10-25 黃政文試聽完畢，回覆「標準達標沒問題」。試聽頁 `karaoke.html`（17 段，約 5.5 MB，內嵌音檔）由 `cp13_real.py` 產生：

- 每個字照估算時間在播放時變黃。
- 已在內建瀏覽器確認 17 段都能載入，播到結尾時所有字都已變黃。
- 字變黃的時間點跟不跟得上聲音由黃政文判斷（Claude 沒辦法聽音檔）；沒有逐字記錄不準的字數，只有整體通過的結論。

## 7. 限制與已知問題

1. **VoAI 沒有逐字標準答案**：只量得到句首，句中每個字準不準靠試聽確認，試聽只有通過與否，沒有數字。
2. **句首參考值來源不明**：參考是專案既有的字幕時間，量出的誤差也包含參考值本身的誤差。22 個句首有 13 個比參考晚 40～80 ms，可能是字幕本來就提早一點出現。
3. **沒有新合成任何配音**：VoAI 金鑰在這台電腦解不開，Audio8Voice、Speech-to-subtitle 這台電腦都沒有安裝，所以都沒有實測。
4. **Windows 語音結果偏樂觀**：它是較舊的合成方式，節奏比神經網路配音規律。
5. **數字與英文的音節是粗估**：日期、電話、小數、英文縮寫的念法跟規則不同時，會偏掉。
6. **有些音檔沒測**：語速特別快、整句沒有停頓、配音裡混了背景音樂的音檔都沒測。估算必須用乾淨的配音檔，不能用混音後的檔案。
7. **台詞必須和配音一致**：字幕改字但配音沒重新生成時，估算會整段偏掉。
8. **短而輕的停頓會漏掉**：句間停頓短於 100 ms 而且不夠安靜時會漏掉，只能靠「最安靜的地方」補位，誤差會到 100～170 ms。

## 8. 可重現性

```
程式碼: tools/spike-cp13/
  - cp13_align.py 估算方法與 Windows 語音評分
  - cp13_real.py  真實配音評分，並產生試聽頁
  - sapi_gen.ps1  用 Windows 語音念 lines.txt，輸出 WAV 與逐詞事件
  - lines.txt     11 句測試台詞
需要: numpy；Windows 要有 Microsoft Hanhan Desktop 語音
執行步驟（在專案資料夾，<輸出資料夾> 自訂）:
  1. powershell -NoProfile -ExecutionPolicy Bypass -File tools\spike-cp13\sapi_gen.ps1 -Dir <輸出資料夾> -Rate 0
  2. 同上，把 -Rate 0 改成 -Rate 3
  3. python tools\spike-cp13\cp13_align.py <輸出資料夾> 30
  4. python tools\spike-cp13\cp13_real.py <輸出資料夾> 30
```

- 第 4 步讀 `data/projects/p_7ijfziw642`，並在輸出資料夾寫出 `karaoke.html`。`data/` 不進 Git，只有開發機有這個專案。
- 2026-10-25 從 `tools/spike-cp13` 在新資料夾重跑過一次，數字和上面的表相同。
- 其他人重做約 5 分鐘。
