## 5. 架構（第 2 期）

```
時間軸
  → 找切點：每個轉場串的起點（不切進 xfade 串）
  → 選段：段數 = 並行數 × 2，每段 ≥ 30 秒，取最接近等分位置的切點
  → 每段一個 ffmpeg 程序（並行數由 S1 決定，NVENC 留 1 個給其他程式）
       只開這段用到的鏡頭與上層片段
       主軌 concat 後 setpts 加上段落起點（以格數算的精確有理數），段內一律用時間軸時間
       跨段的上層片段：入點加 (a − on) × 速度、長度截到段尾、時間戳從 a 開始
       ass、調整圖層、淡入淡出照舊（時間軸時間）
       輸出前 setpts 歸零，只輸出畫面（-an）
  → 聲音：整條時間軸一次做成 WAV（plan_audio_export，有響度時套第二階段），和畫面各段同時跑；聲音沒改時沿用上次的 WAV（P3-4）
  → 接合：各段 -c copy 接起來＋WAV 轉 AAC＋faststart → 輸出資料夾
進度：各段長度加權的總和
取消：結束全部子程序，清暫存資料夾
```

退回規則：

| 情況 | 做法 |
|---|---|
| 時間軸 < 120 秒，或可用切點 < 1 個 | 走現行單一濾鏡圖 |
| 任一段 NVENC 失敗（不是同時上限） | 全部段改用 libx264 重做（接合要求每段編碼參數一致） |
| NVENC 同時上限錯誤 | 降低並行數，重做該段 |
| 接合或混音失敗 | 退回單一濾鏡圖重做一次，log 記原因 |

## 7. Pre-mortem

### Q1、Q2：可能失敗的點與機率

| 失敗點 | 機率 | 依據 |
|---|---|---|
| 分段平行快不到 2 倍 | 35% | 約 32 分鐘沒有歸因；若瓶頸在共用的磁碟或記憶體頻寬，多程序不會線性變快 |
| 接縫重複或缺格、聲音漂移 | 35% | mp4 接合常遇到 B 幀延遲的編輯清單；29.97 fps 時間戳不是整數 |
| 跨段上層片段時間錯位 | 25% | 入點換算牽涉速度、圖片循環、關鍵幀；有 E7 但沒實測 |
| 多程序合計記憶體反而更高 | 20% | 每段仍要開該段全部輸入；S5 前不知道單一解碼器吃多少 |
| 限制解碼執行緒讓主軌變慢 | 20% | 主軌一次只解一個檔，執行緒少可能拖慢 |
| NVENC 同時上限 | 15% | E9 是 D 級 |
| geq 移位後畫面可見差異 | 10% | 數學上等價（不透明度在一格內是常數），只差捨入 |
| **第 2 期整體達不到 ≤ 40% 時間且接縫正確** | **50%** | 前兩項任一發生 |

有兩項超過 30%：第 2 期之前必須先做 S0、S1、S2a。

### Q4：對策

| 失敗點 | 對策 |
|---|---|
| 加速不足 | 依 S0 結果改成「依上層片段數量分配」選段，或並行數降到 2 |
| 接縫 | 改用 ts 或 raw h264 接；再不行用 Q6 備案 C |
| 跨段錯位 | 跨段的上層片段改成整個放進前一段（段界移到它結束後） |

| 主軌變慢 | 只限上層片段輸入，主軌維持預設 |

### Q5：放棄條件

1. S1 最佳並行數下 < 1.5 倍，或合計記憶體壓不到 24 GB 以下：停止第 2、3 期，只交付第 0 期。
2. S2a 三種容器都無法做到格數相等、時間戳等間距：改用備案 C；備案 C 也達不到第 3 節品質，停止第 2 期。
3. 第 2 期工時超過悲觀估計（24 小時）：暫停，交付已驗證部分。

## 10. 不做的選項

| 選項 | 不做的原因 | 等級 |
|---|---|---|
| CUDA 解碼 | 實測 234 fps，比 CPU 的 324 fps 慢，還要搬回系統記憶體 | A |
| GPU 合成（像 FCPX 用 Metal 做合成） | 去背、geq 關鍵幀、ass、lut3d 都要改寫成 GPU 版本，等於重寫輸出引擎 | D（沒量測，依改動範圍判斷） |
| 調高 `-filter_complex_threads` | 預設應已是 CPU 數，切片平行已經開著；S0 順便跑一次指定值確認（**沒有跑**，GAPS #699） | D（記憶中的文件內容，`ffmpeg -h long` 沒寫預設值） |
| NVENC 換較快的 preset | 編碼器使用率約 25%，不是瓶頸 | A |
| 背景預先算圖（像 FCPX 的背景渲染） | 要另做工作排程與失效判斷；第 3 期快取先拿到「改一小段只重算一段」的效果 | 範圍外 |

### 11.3 第 2、3 期

**S2b 接縫畫面**（未編碼 framemd5，各取 0 到 120 秒、含 3 個接縫）：

| 樣本 | 接縫（秒） | 修正時鐘前不同格 | 修正後 |
|---|---|---|---|
| A | 39.333、69.533、106.367 | 202／3,600 | 0／3,600 |
| B | 44.4、81.433、117.1 | 395／3,600 | 0／3,600 |
| D | 33.233、64.5、94.967 | 3／3,600 | 0／3,600 |

修正前的原因：字幕濾鏡（libass）把畫格時間截成整毫秒，字幕事件以 1／100 秒計，`開始 ≤ 現在 < 結束` 才顯示。主軌經 concat 後時間基是微秒、時間戳是各串四捨五入長度的累加，分段後起點不同，捨入也不同；落在整毫秒的格（30 fps 時每 0.1 秒一格）有時被讀成早 1 毫秒，開始或結束剛好在那裡的字幕就晚一格出現或多停一格。時間基改成 1／fps 也不夠：30 fps 第 111 格仍讀成 3,699 毫秒。

修法（`export.py`）：主軌接合後 `settb=1/fps,setpts=N+段落起點`，每格時間就是 N／fps；ass 前後換成細時間基並加 1 刻度（`settb=1/(2000q),setpts=PTS+1,ass=…,settb=1/fps`），截斷後剛好是正確的毫秒。用 vf_ass 的換算式逐格計算 24 到 60 fps（含 29.97、59.94、23.976）各 10 小時，0 格讀錯。

**實作偏離（R8）**：這個修法也改了 `window=None` 的單一濾鏡圖，P2-1「濾鏡圖和現在逐字相同」沒有做到（另有第 0 期加的解碼 `-threads`）。舊版與新版單一濾鏡圖的未編碼畫格：

| 樣本 | 範圍 | 不同格 | 在字幕開始或結束的格 | 其他 |
|---|---|---|---|---|
| B | 0 到 120 秒 | 396／3,600 | 15 | 381 |
| C | 整支 | 0／6,477 | 0 | 0 |
| D | 0 到 120 秒 | 3／3,600 | 3 | 0 |

不同格全部落在整毫秒的格上。字幕邊界格是整句字幕早或晚一格（Y 差 180 到 194）；新版才是對的（`test_one_graph_shows_a_caption_on_exactly_its_frames`）。B 其他 381 格的差異在畫面頂端約 100 像素內的小區域（多數幾十個像素、Y 差多為 18 到 25、最大 52；差異圖裡是畫面中的數字），不是字幕（B 的字幕在下方、沒有動畫標籤）；推測是時間戳差不到 1 微秒時選到來源影片的相鄰一格，哪一版對沒有查證。差異大小是用修正前「分段與單一濾鏡圖」的比對推算（兩邊列出的 200 格裡 199 格重合），舊版與新版之間沒有直接量像素差；A 沒有做舊版與新版比對（GAPS #695、#696）。
