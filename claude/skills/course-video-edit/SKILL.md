# 課程影片後製（course-video-edit）

## 這套 SKILL 做什麼

使用者給一個課程資料夾（講師綠幕影片、PPTX、逐字稿 docx），Claude 用 Video Console（VC）的 API 建好專案，交給使用者在 VC 裡檢查、自己輸出。

成品結構（時間軸由左到右）：

| 段落 | 內容 | 長度 |
|---|---|---|
| 片頭 | `集保數位學習平台-片頭.MP4`，出點裁在 5.64 秒，再交叉淡化 0.5 秒進標題 | 5.64 秒（檔案 6.64 秒） |
| 標題 | 第 1 張投影片滿版 | 2 秒 |
| 講師 | 講師去綠幕、背景 `集保底圖.png`，投影片疊在「投影片」軌 | 依剪輯 |
| 片尾 | `集保數位學習平台-片尾LOGO.jpg` + 音訊軌 `集保數位學習平台-片尾音訊.m4a` | 6.016 秒 |

**限制先說**：

- Claude 聽不到聲音。換頁時間、講錯重講的判斷，靠語音轉出的字幕對照逐字稿，不是聽音檔；字幕辨識錯的地方可能判斷錯，回報時要寫明。
- 伺服器沒有合成單張畫面的 API：去背效果、講師位置、投影片框要在 VC 預覽畫面看（瀏覽器開 VC 的專案，步驟 7 有全解析度抓圖法）。預覽用的是代理檔，輸出時 ffmpeg 去背的邊緣可能略有不同。
- 響度正規化（−16 LUFS）只存在輸出選項，不存在專案裡。專案用壓縮器 makeup 拉到接近 −16 LUFS、限制器 −1 dB 防爆音；輸出時請使用者選「響度 −16」。
- **不輸出影片，也不做測試輸出**：輸出會記錄在專案的輸出清單，使用者會自己檢查後輸出。

## 需要的環境

| 項目 | 檢查方式 | 沒有時 |
|---|---|---|
| Video Console | `python <VC>/tools/vc_client.py status` | 照 `<VC>/docs/CLAUDE_SETUP.md` 設置 |
| ffmpeg、ffprobe、pdftoppm | `ffmpeg -version`、`pdftoppm -v` | 系統 PATH；pdftoppm 來自 poppler |
| PowerPoint（轉 PPTX） | `slides` 指令用 COM 開 PowerPoint | 請使用者自己匯出 PDF 放進 `slides/`，再手動跑 pdftoppm |
| 語音轉字幕 | `status` 顯示「語音轉字幕：就緒」 | 無法轉字幕，停在 prepare，告訴使用者 |
| Python 套件 | numpy、pillow、python-docx、pywin32 | 先查已安裝，缺的才裝 |

## 版面規則（量自過去成品，之後不需要再看舊影片）

1920x1080 畫面座標：

- **投影片框**（左上 x、上 y、寬 w，以畫面比例表示，高度依圖片比例）：
  - 16:9 投影片：x 0.0099、y 0.1769、w 0.70（約 19,191 起，1344x756）
  - 4:3 投影片：x 0.0589、y 0.137、w 0.570（約 113,148 起，1094x821）
  - 腳本依投影片 PNG 的長寬比自動選。
- **講師**：去綠幕後頭頂約在 y 390（舊片 375 與 410），身體中線約在 x 1660，腳底切在畫面底部。
  - 縮放 s = (1080 − 390) / (1080 − 原片頭頂)
  - transform.x = (1660 − 960 − (原片中線 − 960) × s) / 1920
  - transform.y = −(1 − s) / 2（讓底邊留在 1080）
  - 原片頭頂已低於 390 時不縮放（s = 1）。
- **字幕**：專案預設樣式用 Owner 常用的「常用：白字細黑框」（新專案的起始樣式：白字、細黑框 2.5、無陰影、字級 84、下邊距 42），不另建課程樣式；專案沒有這個樣式時腳本補上並設為預設。每句最多 20 字（字級 84 下 20 字約 1280px，不會換行）。
- **無露臉講師**：投影片改成滿版（overlay `full: true`），講師鏡頭關畫面（`pictureHidden`，時間軸上的 V），原聲分離成獨立音訊片段並保持對齊；使用者之後在 VC 打開 V 就能看到講師畫面，聲音不會錯位。
  - 參考：舊專案 01（4:3 投影片）、02（16:9 投影片）。

## 流程

工作資料夾建議放在課程資料夾下的 `vc_work\`。腳本在 `scripts/course_edit.py`。

### 1. 轉檔（需要時）

講師原檔是 MXF 或不是 1080p 時，先用 `scripts/transcode.py` 轉成 1080p MP4（放在課程資料夾 `1080p\`）。已經有 1080p MP4 就跳過。

### 2. 投影片轉 PNG

```
python scripts/course_edit.py slides "<課程資料夾>"
```

PowerPoint 匯出 PDF → pdftoppm 轉 `slides\slide-01.png`…（寬 1920，保持原比例）。隱藏投影片不會輸出，腳本會列出來。

**檢查張數**：投影片張數要跟逐字稿 P 段數對得上。對不上時，用 Read 看 PNG，找出多的是哪幾張（例如流程動畫拆成多張、附錄、Q&A），在 plan.json 決定每張的換頁時間或刪掉不用的。

### 3. prepare

```
python scripts/course_edit.py prepare --course "<課程資料夾>" --video "<講師.mp4>" --work "<工作資料夾>" [--name 專案名] [--noface] [--obs "<OBS 錄影>"]
```

- 建 1920x1080 專案（fps 跟講師影片一樣，29.97 也可）、匯入講師到第一個鏡頭、素材庫匯入固定素材與投影片。
- 語音轉字幕；從 3 個畫面量講師頭頂、中線、綠幕顏色，算出 transform；再量綠幕與講師（衣服、皮膚、頭髮）到綠幕色的色距，算出去背強度 similarity／blend（`person.keyParams`）；量音量、靜音段、整體 LUFS。
- 有逐字稿 docx（段落標記 `P1`、`P2`…）時，逐字比對字幕找出每段開始的位置，當作換頁建議。
- 標出「疑似重講」：相鄰 20 秒內說了幾乎一樣的話。
- 寫出 `transcript.json`、`transcript.txt`、草稿 `plan.json`（已存在時不覆蓋）。

`--noface`：使用者指定無露臉的講師（例如「07-數安部介紹.mp4 無露臉」）。

### 4. 讀 transcript.txt，改 plan.json

`transcript.txt` 每行：`序號 字幕id 開始-結束 | 文字`，時間是講師原檔的秒數。

- `▶ P5 換頁建議 123.40（吻合 0.85）`：逐字稿第 5 段從這裡開始。吻合度低於 0.5 要自己對照逐字稿確認。
- `⚠ 疑似重講`：先對照逐字稿。多數是講稿本來就重複的句型（例如「於騎縫處蓋章…並於申請書蓋章」）或語音辨識幻覺，不是重講。真的講錯重講時，把講錯那段放進 `cuts`（從講錯那句開始前的停頓，到重講那句開始前的停頓），保留後面講對的。剪點用該區間的音量確認在靜音裡。
- 字很多但時間很短的字幕（例如 20 字只有 1.5 秒）、或和上一句一字不差緊接著的字幕，通常是辨識幻覺：用 faster-whisper large-v3 對那段重新辨識（`word_timestamps=True`），照實際講的字改字幕，不要剪。
- `[空 2.3s]`：長停頓，剪輯點放在停頓中間。

plan.json 欄位：

| 欄位 | 說明 |
|---|---|
| `mode` | `face` 或 `noface` |
| `start`、`end` | 講師原檔保留範圍（預設第一句前 0.3 秒、最後一句後 1 秒） |
| `cuts` | `[[a, b], …]` 要剪掉的原檔區間（講錯重講、NG、長空白） |
| `slides` | `[{"slide": n, "at": 原檔秒數}, …]`，由小到大；第 1 張從講師開頭就出現；不用的投影片刪掉那一列 |
| `chroma` | `{"on", "color", "similarity", "blend"}`，color 是量到的綠幕中位色；similarity 比綠幕最遠的色距多 0.005，blend 是到講師最近色距的八成（上限 0.1）。暗綠、偏灰的綠幕 similarity 會很小（約 0.05），不要改回 0.18 這類通用值，否則深色衣服、皮膚會被去掉 |
| `transform` | 講師位置縮放（腳本已算好） |
| `denoise` | `{"on": true, "sample": {"from", "to"}}`，樣本是講話以外最長的靜音（0.25 到 10 秒） |
| `comp` | `{"makeup", "limiter": true, "limiterThreshold": -1}`；makeup = −16 − 整體 LUFS |
| `captions` | `{"edit": {字幕id: 新文字}, "delete": [字幕id]}`：同音字、專有名詞照逐字稿改 |
| `maxChars` | 每句字幕字數上限（20），超過的自動拆句 |

字幕修正原則：專有名詞、數字、機構名以逐字稿為準；講師口語多出的贅詞（呃、那個）可刪；逐字稿與實際講的不同時，以實際講的為準（字幕要對嘴）。

### 5. apply

```
python scripts/course_edit.py apply "<工作資料夾>\plan.json"
```

只能套在剛 prepare 完的專案（只有一個鏡頭、沒有疊加）。要重來：在 VC 復原到套用前，或重新 prepare（新專案）。

片頭檔案 5.64 秒起自己淡出到黑，6.00 到 6.64 秒全黑（聲音 5.70 秒就沒了）；不裁的話交叉淡化是從黑畫面淡進標題，看起來像中間進了黑畫面。apply 把片頭出點設在 `INTRO_OUT`（5.64），verify 出點超過就報錯；換片頭檔時用 ffmpeg signalstats 量 YAVG 重找淡出起點再改 `INTRO_OUT`。

片頭、標題、片尾的長度與淡化是放進去之後才調的，字幕不會跟著動；apply 最後量字幕相對講師的位移（中位數），整批移回去。

做的事：講師鏡頭裁頭尾、去綠幕＋集保底圖、位置縮放、降噪、壓縮器＋限制器 → 剪掉 cuts（字幕跟著刪與位移）→ 前面放片頭＋標題、後面放片尾＋片尾音訊 → 「投影片」軌依換頁時間放投影片（或 OBS 錄影） → 字幕樣式與修正 → noface 時隱藏講師畫面並分離原聲。

### 6. verify

```
python scripts/course_edit.py verify "<工作資料夾>"
```

檢查畫面軌順序、講師鏡頭的去背／背景／壓縮器、講師總長、投影片有無空檔或重疊、字幕與講師的對齊（誤差 0.05 秒內）、字數、字幕不超出講師段落、片尾音訊位置。

### 7. 在 VC 預覽畫面看（必做）

瀏覽器開 VC 該專案，至少看：講師去背邊緣（綠邊、破洞）、講師位置與投影片框不重疊、片頭到標題的淡化（5.1 到 5.6 秒之間要看得到片頭與標題頁疊在一起，不能有黑畫面）、片尾。去背有綠邊就調高 similarity（每次 0.01），講師身上破洞、半透明就調低。

預覽畫面太小看不出邊緣時，在 VC 頁面的 console 抓全解析度合成畫面（含集保底圖，不含字幕），放大看：

```js
const sf = await import("/js/lib/scope-frame.js");
const g = document.querySelector(".pl-graded"), raw = document.createElement("canvas"), out = document.createElement("canvas");
sf.grabFrame(g, raw, out, 1920);                 // 第一次載入底圖
await new Promise(r => setTimeout(r, 1000));
const img = sf.grabFrame(g, raw, out, 1920);     // ImageData 1920 寬
```

## 沒有逐字稿：OBS 錄簡報

使用者會用 OBS 錄講師講課時的簡報畫面（含現場收音）。

```
python scripts/course_edit.py prepare … --obs "<OBS 錄影.mp4>"
```

- 腳本比對兩段聲音的音量包絡，算出「OBS 時間 = 講師時間 + offset」，列出明確度（1.5 以上才算可靠，低於要人工看）。
- apply 時 OBS 錄影放在投影片框，每個講師片段配一段，`in` 依 offset 對齊，音量 0（只用講師收音）。plan.json 的 `slides` 不用填。
- **[Spike]**：offset 演算法只用合成位移測過（加噪、低通、回音、截短，誤差 ≤3 ms），尚未用真實 OBS 錄影驗證。第一次用時要在 VC 看投影片換頁是否跟講師講的對得上，並回報結果。

## 回報格式

每個專案：專案名、片長、剪掉的段落（原檔時間＋原因）、換頁時間有疑慮的投影片、字幕修正對照表、投影片與逐字稿張數不一致的處理、沒驗證到的部分（聲音、去背需人工看）。提醒使用者輸出時選「響度 −16」。

## 已知限制

- 換頁建議靠字幕比對：講師脫稿很多的段落吻合度低，需要人工判斷。
- 去背參數是從 3 個畫面量的綠幕中位色與色距，燈光不均或講師穿綠色系時邊緣可能有綠邊或破洞，要在預覽畫面調；腳本在講師色距貼近綠幕時會印警告。
- 講師量測假設綠幕畫面中只有講師（x 240 到 1680 之間），畫面裡有其他人或道具會量錯頭頂。
