# 腳本轉 VC 分鏡表（script-to-vc-storyboard）

## 這套 SKILL 做什麼

使用者給一份腳本，Claude 當導演拆成靜態分鏡，交出一份 Video Console（VC）能直接匯入的 Word 分鏡表：

1. 讀腳本：`scripts/read_script.py` 把 Word 段落與表格依原順序轉成純文字。
2. 設計分鏡：Claude 讀完整份腳本，照下方「分鏡設計規則」寫 `shots.json`。
3. 產出 Word：`scripts/build_docx.py` 把 `shots.json` 寫成分鏡表，欄位寫法和 VC 細拆分鏡一致。
4. 自檢：`scripts/check_import.py` 用 VC 原始碼離線匯入這份 Word，一般匯入與細拆分鏡兩種模式都要逐鏡逐欄和計畫相同。
5. 回報：鏡數、總長、長度分布、各段鏡數，以及沒驗證到的部分。

每一列都寫明秒數，所以 VC 匯入時一列就是一鏡，細拆分鏡也不會再拆。

**限制先說**：

- Claude 看不到生成後的畫面、聽不到配音。秒數依字幕字數（每秒 4 個中文字）估算，畫面是否好看、AI 生圖是否照描述畫，要匯入 VC 生成後由人看。
- 分鏡的節奏與美感來自 Claude 的判斷，不是程式算出來的。自檢只保證 VC 匯入後內容和計畫一字不差、字幕讀得完。
- 自檢需要 VC 原始碼（`app/vc/script.py`）。只有安裝版 exe、沒有原始碼時無法自檢，要改成實際匯入 VC 目視確認。

## 需要的環境

| 項目 | 檢查方式 | 沒有時 |
|---|---|---|
| Python 3.10 以上 | `python --version` | 先安裝 Python |
| python-docx | `python -c "import docx"` | `python -m pip install python-docx` |
| VC 原始碼 | 資料夾內有 `app/vc/script.py` | 依序找 `--vc`、環境變數 `VC_ROOT`、SKILL 所在的 VC 資料夾、`F:\AI Project\Video Console`；都找不到就無法自檢 |

自檢不會呼叫正在執行的 VC，也不會改動任何專案。

## 工作資料夾

`<腳本所在資料夾>/VC分鏡/`，內含：

- `腳本內容.txt`：read_script 產生，給 Claude 讀
- `shots.json`：Claude 寫的分鏡計畫
- `<腳本檔名>-VC分鏡表.docx`：交給使用者匯入 VC 的檔案
- `檢查報告.txt`：check_import 產生

## 流程

```bash
python <SKILL>/scripts/read_script.py "<腳本.docx>"
```

讀 `VC分鏡/腳本內容.txt` 全文（Read 工具，不要只看終端機，中文在終端機常是亂碼）。先找出段落結構與每段情緒強度，再寫 `VC分鏡/shots.json`，然後：

```bash
python <SKILL>/scripts/build_docx.py "<腳本資料夾>/VC分鏡/shots.json"
```

```bash
python <SKILL>/scripts/check_import.py "<腳本資料夾>/VC分鏡/shots.json"
```

讀 `檢查報告.txt`。「問題」要修到 0 個（改 `shots.json`，重跑 build 與 check）；「提醒」逐條判斷要不要改。結束代碼 0 才算通過。

在 VC 匯入：專案的「匯入劇本」，按「開啟檔案」選這份 Word，一般或細拆分鏡都會得到同樣的鏡頭。

## shots.json 格式

```json
{
  "title": "片名",
  "source": "原腳本檔名.docx",
  "characters": {"小明": "十歲男孩，短髮，藍色條紋上衣，背黃色書包"},
  "shots": [
    {
      "act": "第一幕 上學途中",
      "scene": "社區街口",
      "size": "遠景",
      "picture": "清晨的社區街口，小明背著書包走出巷子，暖色晨光，畫面左低右高的對角構圖",
      "motion": "小明由左向右走入畫面",
      "move": "緩慢推進",
      "caption": "每天早上，小明都自己走路上學",
      "speaker": "旁白",
      "notes": "音效：鳥鳴、遠處機車聲",
      "duration": 4.5
    }
  ]
}
```

| 欄位 | 必填 | 寫法 | 在 Word 分鏡表變成 |
|---|---|---|---|
| `act` | 否 | 幕或段落名，同一段連續的鏡頭寫同一個 | 每段一個標題與一張表（VC 會合併成同一份） |
| `scene` | 是 | 場景短名，8 字內 | 鏡頭名稱「場景（景別）」 |
| `size` | 是 | 景別，見下方景別表 | 畫面開頭「景別：」、運鏡開頭「景別，」 |
| `picture` | 是 | 這一格畫面的靜態描述 | 畫面 |
| `motion` | 否 | 人物與物件怎麼動，一兩句 | 動作 |
| `move` | 否 | 攝影機怎麼動，見景別表 | 運鏡 |
| `caption` | 否 | 這一鏡聽到的旁白或台詞，只寫話本身 | 字幕 |
| `speaker` | 否 | 說話的人；旁白寫「旁白」 | 備註第一行「說話者：X」 |
| `notes` | 否 | 音樂、音效、後製字卡、轉場等，多項用換行 | 備註 |
| `duration` | 是 | 秒數，0.5 到 60，取到小數一位 | 秒數 |

`characters` 會在每鏡畫面中角色名字第一次出現的地方補上外觀（已經有括號說明的不補），讓 AI 每鏡都畫出同一個人。外觀只寫穿著、髮型、年齡、體型等看得見的特徵。

## 分鏡設計規則（節奏與美感）

### 先找結構，再決定鏡數

1. 讀完整份腳本，切出段落：開場、鋪陳、衝突或高潮、收尾；標出每段是舒緩、平穩還是緊湊。
2. 每一段用 2 到 5 個不同景別或角度的鏡頭拍，一段只有一鏡是錯的。
3. 總鏡數抓「總秒數 ÷ 2.3 到 3.4」。參考兩支已完成的片：
   - 兒少安全動畫（節奏快、驚險段多）：78 鏡、約 265 秒，中位數 2.3 秒；1.5 秒以下 24 鏡、1.5 到 3 秒 19 鏡、3 到 5 秒 16 鏡、5 秒以上 19 鏡。
   - 公部門議題動畫（敘事穩、旁白多）：47 鏡、約 169 秒，中位數 3.2 秒；四個區間 6、15、15、11 鏡。
   - 長短要拉開，四個區間都要有鏡頭。連續 4 鏡同秒數，自檢會提醒。
4. 一次最多 200 鏡；超過就分成兩份腳本做。

### 腳本已經寫好的，照它拆

- 編號動作（1. 2. 3.）一個動作一鏡。
- 寫了（特寫）的就是一個特寫鏡。
- 對話每位說話者至少一鏡說話鏡頭，必要時接一個聽的人的反應鏡頭。
- 備註裡的鏡頭指示（例如「鏡頭：由窗外拉進」）就是一鏡，照它的運鏡寫。
- 資訊圖卡、法規說明：旁白依圖卡分格順序分到各鏡，每鏡一個重點。
- 旁白列舉（A、B、C）一項一鏡。
- 想像、危險預演、閃回：1 到 3 個 0.5 到 1 秒的極短鏡，前後接人物反應。
- 分割畫面、劇中劇（電視畫面裡的戲）：先給一鏡交代載體（電視、手機、分割框），再進內容。
- 特效與效果字（磚牆浮現、泡泡框、畫面上跳出的字）：畫面只寫看得到的光影或物件，特效寫進 `notes`「視覺特效：…」，要出現的字寫「後製字卡：…」。
- 內心獨白：`speaker` 寫「角色名（內心獨白）」；兩人同時說寫「甲、乙」。
- 一句旁白配多個畫面（蒙太奇、列舉）：照逗號切開，一個畫面配一段。

### 每鏡長度

| 鏡頭 | 秒數 |
|---|---|
| 開場、新場景的建立鏡頭 | 4 到 6 |
| 一般動作 | 2 到 3.5 |
| 特寫、插入特寫、反應 | 1.5 到 2.5 |
| 想像、危險閃現 | 0.5 到 1 |
| 有字幕的鏡頭 | 至少字幕讀完的時間：中文字數 ÷ 4 + 英數詞數 ÷ 2.5 + 0.2 秒，無條件進位到 0.1 秒（標點不算字） |
| 情緒收尾、片尾 | 5 以上 |

- 寫 `shots.json` 時就逐句算好字幕下限再定秒數，不要等自檢報錯才補。例：「可是，如果我為他們說話」10 字，10 ÷ 4 + 0.2 = 2.7 秒，寫 2.6 會被列成問題。

- 旁白很長時，在停頓處（逗號、句號）切開，分到這段的幾個鏡頭，每鏡只放自己那一句，不要一句字幕撐一個 10 秒的鏡。
- 舒緩、感性的段落：鏡數少、每鏡長；緊張、快的段落：鏡數多、每鏡短。
- 一段的開頭通常是較遠的景別，往近景、特寫推進；高潮後用一個較長的遠景或中景讓觀眾喘口氣。

### 景別與運鏡

VC 細拆分鏡使用的景別與運鏡，優先從這裡選，風格才會和 VC 自己拆的鏡頭一致：

| 景別 | 用途 | 舒緩時運鏡 | 緊湊時運鏡 |
|---|---|---|---|
| 遠景 | 交代地點、時間、人物位置 | 緩慢推進 | 快速推進 |
| 中景 | 人物動作、兩人互動 | 固定鏡頭 | 手持跟拍 |
| 近景 | 表情、說話 | 緩慢推近 | 手持 |
| 側面中景 | 行走、移動、換個角度 | 緩慢橫移 | 快速橫移 |
| 插入特寫 | 手、物件、關鍵細節 | 固定鏡頭 | 快速推近 |
| 特寫 | 情緒高點、眼神 | 緩慢推近 | 手持 |
| 反應鏡頭 | 聽的人、旁觀者的反應 | 固定鏡頭 | 手持 |

也可用全景、大特寫、過肩鏡頭、俯拍、仰拍、主觀鏡頭。相鄰兩鏡避免同景別同角度（跳接感）。

### 畫面怎麼寫

- 順序：主體與動作、場景、光線與時間、構圖。例：「小明蹲在斑馬線前綁鞋帶，背景是放學時段的十字路口，夕陽逆光，人物在畫面左三分之一」。
- 一鏡一個畫面，只寫這一格看得到的東西，不寫「然後」「接著」。動態放 `motion`，攝影機放 `move`。
- 同一段的場景、天氣、時間、角色穿著要一致；角色外觀寫在 `characters`，不要每鏡自己改寫。
- 畫面不要再寫外觀已有的服裝與配件（外觀寫了粉紅色書包，畫面就不寫「背著粉紅色書包」；外觀寫了坐著輪椅，畫面就不寫「坐在輪椅上」），否則補上外觀後會重複。拿起、摸、吹這類動作可以照寫。
- 某鏡刻意換裝時，名字後面自己加括號，例如「小宜（穿著睡衣）」，外觀就不會補進去。
- 角色外觀要從腳本或使用者提供的角色設定來；腳本沒寫時，向使用者要角色設定圖或成片截圖，並在回報說明外觀是推定的。
- 畫風（例如 3D 動畫、水彩）交給 VC 專案的風格設定，不寫在每鏡畫面裡，除非這一鏡刻意換風格（例如劇中劇、回憶）。

## 格式規則（讓 VC 匯入後一字不差）

違反這些規則，VC 會改寫內容，自檢會列成「問題」：

1. **字幕只寫話本身**：不加「」、句尾不加句號（VC 會去掉）；說話者不要寫在字幕開頭（「媽媽：小心」會被 VC 拆成說話者），改填 `speaker`。字幕不要用（…）開頭。
2. **畫面不畫字**：VC 生圖時一律要求不畫文字。`picture`、`motion`、`move` 不要出現「字卡、字幕、標題、片名、標語」（VC 會把整句移到備註）。招牌、圖卡、法規條文上的字，寫進 `notes`「後製字卡：…」，畫面只寫「空白的告示牌」「圖卡版面」。
3. **秒數**：每鏡都要有，0.5 到 60 秒，且不短於字幕讀完的時間。
4. **長度上限**：鏡頭名稱 60 字、畫面 4000 字、動作 2000 字、運鏡 200 字、字幕 500 字、備註 2000 字。
5. **不用破折號**（U+2014 與連續兩個 U+2014），改用逗號、冒號、括號。
6. **欄位開頭結尾不放標點**：build_docx 會去掉頭尾的逗號、句號、冒號、頓號（VC 也會）。

## 測試紀錄

| 腳本 | 腳本格式 | SKILL 產出 | 成片 |
|---|---|---|---|
| 礁溪社福兒少安全 | 段落與表格混合，14 段 | 103 鏡、308 秒、中位數 2.7 秒，問題 0、提醒 0 | 78 鏡、約 265 秒 |
| 宜蘭縣政府隱形圍牆（改寫版） | 每幕一張表，編號動作與（特寫）多 | 99 鏡、283.5 秒、中位數 2.6 秒，問題 0、提醒 0 | 依原稿製作，47 鏡、約 169 秒 |

兩份分鏡表也經 VC 伺服器實際上傳、拆解（一般與細拆）、加入專案，鏡頭各欄、秒數、字幕與計畫 0 差異。

分鏡總長比成片長，是因為腳本每句台詞都保留，且每鏡不短於字幕讀完的時間（每秒 4 字）；隱形圍牆改寫版的台詞也比原稿多。要對齊成片長度，刪掉成片不會用的旁白或台詞，不要把秒數壓到讀不完。

## 回報

給使用者：

- Word 分鏡表路徑，以及在 VC 怎麼匯入（一句話）。
- 鏡數、總長、中位數、四個長度區間的鏡數、各段鏡數與秒數（從 `檢查報告.txt` 抄）。
- 設計重點：哪幾段放慢、哪幾段加快、腳本裡哪些地方是照原腳本指示拆的、哪些是 Claude 加的鏡頭。
- 自檢結果：問題 0 個；提醒有幾個、保留的理由。
- 沒驗證到的部分：畫面生成效果、配音實際長度、畫面與聲音的對位。
