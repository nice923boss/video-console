# 訪談影片剪輯（interview-video-edit）

## 這套 SKILL 做什麼

使用者給一個資料夾，裡面是訪談或受訪影片。Claude 用 Video Console（VC）的 API 全程操作：

1. 轉檔：攝影機原檔先判斷大小與編碼，放得進 VC 就保留原畫質只換成 MP4 容器，太大或瀏覽器不能播才轉 1080p H.264（`scripts/transcode.py`）。
2. 分組：一位受訪者一個 VC 專案；同一人被拆成好幾個檔案時放在同一專案、依檔名排序成多個鏡頭。
3. 準備：建專案、匯入、語音轉字幕、量音量，寫出逐字稿 `transcript.txt`（`interview_edit.py prepare`）。
4. 判讀：Claude 讀逐字稿，寫 `plan.json`（要標記或刪除哪些段落、字幕怎麼改）。
5. 套用：`interview_edit.py apply`，然後 `verify` 檢查、`export` 輸出 SRT。
6. 回報：每位受訪者的標記清單、字幕修正對照表、待確認清單、沒驗證到的部分。

**限制先說**：Claude 聽不到聲音。判斷誰在說話、哪裡講錯，靠的是字幕內容、說話音量（`transcript.txt` 每句的 dB）與停頓長度，不是聽音檔。回報時要寫明這一點。

## 需要的環境

| 項目 | 檢查方式 | 沒有時 |
|---|---|---|
| Video Console | `python <VC>/tools/vc_client.py status` | 照 `<VC>/docs/CLAUDE_SETUP.md` 設置 |
| 環境變數 `VC_ROOT` | 指到 VC 資料夾 | 沒設時用 `scripts/vc_client.py` 內建的預設路徑 |
| ffmpeg、ffprobe | `ffmpeg -version` | VC「設定 › 依賴元件」一鍵安裝，或系統 PATH |
| 語音轉字幕（Speech-to-subtitle） | `status` 顯示「語音轉字幕：就緒」 | 無法轉字幕，整套流程停在第 3 步，告訴使用者 |
| NVIDIA 顯示卡 | 轉檔用 h264_nvenc，語音辨識只跑 CUDA | 轉檔自動改用 libx264（較慢）；語音辨識無法使用 |

VC 沒在執行時 `vc_client.py` 會用 `--no-window` 背景啟動它，不用另外開。執行中的是更新前的程式時會自動換成新版；有工作在跑時沿用舊版並在 stderr 提示，照實轉告使用者。

## 工作資料夾

每位受訪者一個工作資料夾：`<影片資料夾>/剪輯工作/<名稱>/`，內含：

- `transcript.json`：prepare 產生，apply、verify 的依據，不要手改
- `transcript.txt`：給 Claude 讀的逐字稿
- `plan.json`：Claude 寫的剪輯計畫
- `<專案名>.srt`：export 輸出

## 步驟

### 0. 確認模式

- 使用者沒特別說：**標記模式**。
- 使用者說要「移動講者前後的話」「讓對話更順」「直接剪掉」「重組」：**重組模式**。
- 使用者人不在、說「你判斷就好」時不要停下來問，照上面規則選，回報時說明選了哪個模式。

### 1. 轉檔

```bash
python "<SKILL>/scripts/transcode.py" "<影片資料夾>"
```

VC 單檔上限 4 GB。VC 從 2026-11-06 起可以直接匯入 MXF（畫面是 H.264 4:2:0 8-bit 時只換外殼、自動選最大聲的音軌），但太大或瀏覽器不能播的仍要先轉，所以批次照樣先跑腳本，每支先判斷，不是一律轉 1080p：

| 條件 | 做法 | 原因 |
|---|---|---|
| 影像是 H.264（或 VP9、AV1）4:2:0 8-bit，且保留原畫質的估計大小在 3.9 GB（上限的九成）以內 | `remux`：影像原封不動複製進 MP4，只把聲音轉 AAC，每支幾秒 | 畫質零損失，4K 留給防抖裁切與推近；VC 預覽解析度設 1/2、1/4 時會自己做小的預覽檔 |
| 超過 3.9 GB（例如 4K 100 Mbps 約 5 分鐘以上的長訪談） | `scale`：轉 1080p H.264 | 放不進 VC |
| 10-bit、4:2:2（XAVC S-I、XAVC S 4:2:2）、HEVC（XAVC HS）等瀏覽器不能播的編碼 | `scale`：轉 1080p H.264 | 不轉的話 VC 匯入時也會用原解析度重新編碼，更慢更大 |

- Sony FX6 的 XAVC S 4K（H.264 4:2:0 8-bit）短片段實測（2026-11-05，43 支共 3.8 GB，最大 226 MB）：全部判成 `remux`，影像逐格解碼與 MXF 相同。
- 輸出在 `<影片資料夾>/vc_mp4/`，檔名和原檔同名（VC 陀螺儀防抖靠同名找原始檔）；已做過且長度正確的檔案會跳過。
- `--mode scale` 強制全部轉 1080p（輸出在 `1080p/`，和 1.6.0 以前相同）；`--mode remux` 只要放得進 4 GB 就保留原畫質。
- 攝影機常錄 4 個單聲道音軌、只有一軌有麥克風：腳本量每軌音量，自動選最大聲的那軌（短於 20 秒的片段從頭量）。
- 讀 `vc_mp4/transcode_report.json`：每支的 `mode`、`reason`、長度、選了哪一軌、`problems` 是否為空；回報時寫幾支保留原畫質、幾支轉 1080p、為什麼。
- `remux` 很快；`scale` 的 4K 長片要數分鐘到數十分鐘，用背景執行。

### 2. 分組

一位受訪者一個專案。判斷同一人的依據（由強到弱）：

1. 每支抽一張畫面看人：`ffmpeg -v error -ss 3 -i x.mp4 -frames:v 1 -vf scale=480:-2 x.jpg`，用 Read 看圖，看完刪掉。
2. 檔名編號連續、其中一支特別短（常是開拍後中斷重來）。
3. 轉完字幕後，自我介紹的姓名、內容是否接續。

同一人的多個檔案放進同一個 prepare 指令，依檔名順序。

### 3. 準備（每個專案一次）

```bash
python "<SKILL>/scripts/interview_edit.py" prepare --name "<專案名>" --work "<工作資料夾>" a.mp4 [b.mp4 ...]
```

- 建專案（1920×1080、30 fps）、每支影片一個鏡頭、匯入、每個鏡頭各轉一次字幕。
- 180 秒的影片約 2 到 3 分鐘。多個專案可以寫成一個迴圈丟背景依序跑，Claude 邊等邊判讀已完成的。
- 中途失敗或要重產逐字稿：加 `--pid <專案代號>` 再跑一次。專案已有字幕時不會重新匯入或轉字幕。

### 4. 讀逐字稿、寫 plan.json

`transcript.txt` 長這樣：

```
學員受訪_705_7462  pid=p_w9435p5jug  片長 180.51s
說話音量中位 -25.9 dB，底噪 -49.4 dB，靜音門檻 -42.3 dB
鏡頭：705_7462 0.00-180.51

        [靜音 2.2s 2.05-4.20]
001 c_sf4wwadrzt     4.20-    6.15  -31.1dB | 大家好 我叫陳彥霖
...
054 c_ire8z2o4pg   165.54-  167.32  -38.4dB(小聲) | 這樣可以嗎
```

- 時間是**序列秒數**（多鏡頭專案從第一個鏡頭開頭累計），plan.json 的時間直接用這個。
- `(小聲)`：比說話音量中位低 8 dB 以上。採訪者通常離麥克風遠，提問多半是小聲句。
- `[靜音 …]`：字幕之間 1 秒以上的無聲。

要找的段落：

| kind | 是什麼 | 線索 |
|---|---|---|
| `interviewer` | 採訪者提問、引導 | 小聲句、問句（嗎、呢、可以說說…）、和受訪者用詞不同的人稱 |
| `countdown` | 拍攝倒數、開拍口令 | 「三二一」「開始」「好 錄了」，多在開頭 |
| `ng` | 講錯重來 | 同一句話短時間內出現兩次，留後面那次 |
| `confirm` | 確認口語 | 「這樣可以嗎」「好 OK」「要再一次嗎」，多在結尾 |
| `pause` | 停頓過長 | 開頭、結尾的空白，或句間 2 秒以上的無聲（`autoPauses` 自動找） |

### 5. 套用、檢查、輸出

```bash
python "<SKILL>/scripts/interview_edit.py" apply "<工作資料夾>/plan.json"
python "<SKILL>/scripts/interview_edit.py" verify "<工作資料夾>"           # 重組模式加 --restructure
python "<SKILL>/scripts/interview_edit.py" export "<工作資料夾>"           # 加 --video 另輸出 MP4
```

- apply 先送一批字幕修改（一個復原步驟），再送一批分割與標色或刪除移動（另一個復原步驟）。
- apply 發現專案已經分割過會拒絕執行。要重來：在 VC 按 Ctrl+Z 收回到分割前，或「設定 › 版本紀錄」還原。
- verify 檢查：片長（標記模式要和原始一樣）、每句字幕沒跨片段、不重疊、18 字以內、標點空格規則、時間沒漂移（每句字幕仍落在原始辨識的時間內）。不通過時結束代碼非 0，照列出的問題修 plan 或在 VC 修。
- 標記模式只輸出 SRT，使用者決定刪哪些片段後自己在 VC 輸出影片。

### 6. 目視檢查（第一個專案做一次）

用內建瀏覽器開 VC（位址在 `<VC>/data/run/server.json`）的剪輯頁 `#edit`，確認標色片段、字幕列、原聲波形都有顯示。截圖要點名異常（黑畫面、錯誤訊息、缺少的元素）。

## plan.json 格式

```json
{
  "mode": "mark",
  "marks": [
    {"captions": ["c_first", "c_last"], "kind": "interviewer", "note": "採訪者提問，建議刪除"},
    {"start": 0, "end": 3.95, "kind": "pause", "note": "開頭 4 秒沒有說話，評估是否刪除"}
  ],
  "autoPauses": {"min": 2.0, "pad": 0.25},
  "captions": {
    "edit": {"c_xxx": "整理後的字幕文字"},
    "delete": ["c_yyy"]
  },
  "moves": [
    {"captions": ["c_a", "c_b"], "before": "c_z"}
  ],
  "maxChars": 18,
  "review": {
    "corrections": {"辦公辦讀": "半工半讀"},
    "unsure": ["034「全公旅遊」可能是「全公司旅遊」，未改"]
  }
}
```

| 欄位 | 說明 |
|---|---|
| `mode` | `mark`（標記）或 `restructure`（重組） |
| `marks` | 標記模式：要切出來標色的段落。重組模式：要刪除的段落。用 `captions`（第一句、最後一句的代號）或 `start`、`end`（序列秒數）指定 |
| `marks[].kind` | 決定顏色，見下表。也可以直接給 `color`（red、orange、lime、green、blue、purple） |
| `marks[].note` | 寫進片段備註，使用者滑鼠停在片段上看得到 |
| `marks[].name` | 選填，只有標記模式用：片段名稱（時間軸上顯示）。依題目拆段時寫「Q1 題目重點」，見下方「依題目拆段」 |
| `autoPauses` | 自動找句間的長停頓。`min` 最短秒數，`pad` 停頓兩側保留的呼吸秒數。和 `marks` 重疊的部分自動避開。重組模式下找到的停頓會直接刪除 |
| `captions.edit` | 字幕代號對整理後的文字。超過 `maxChars` 的句子 apply 會自動在標點或空格處拆成多句，時間依字數比例分配 |
| `captions.delete` | 整句刪掉的字幕（例如重組模式中被刪段落以外、單純不要的口語） |
| `moves` | 只有重組模式用：把一段（`captions` 或 `start`、`end`）移到某句字幕之前（`before` 給字幕代號，或 `"end"` 移到最後） |
| `review` | 不影響剪輯，給回報用：同音字修正對照表、待確認清單 |

**用字幕指定段落時的邊界**：apply 把切點放在前後句的空隙裡（離語音 0.3 秒，或空隙中點），不會切到字。第一句往前延伸到 0 秒、最後一句延伸到片尾。字幕和鏡頭是依開始時間綁在一起的，切點一定要落在字幕之間，所以**不要用 start、end 切在一句字幕中間**。

**卡住、講到一半停很久的 NG**：用 `captions` 指定時切點只離語音 0.3 秒，前後的長停頓會留在片段外，又被 autoPauses 拆成另外的橘色段，使用者要看好幾段才知道是同一件事。這種情況改用 `start`、`end`，從前一句結尾加 0.3 秒到後一句開頭減 0.3 秒，把卡住的話和停頓包成一段紅色（autoPauses 會自動避開這段）。

## 顏色慣例（標記模式）

| kind | 顏色 | 色碼 | 意思 |
|---|---|---|---|
| interviewer、countdown、ng、confirm | 紅色 | #ff6b6b | 建議刪除 |
| pause | 橘色 | #f5b14c | 停頓過長，評估是否刪除 |

使用者在 VC 時間軸看到紅色、橘色片段，滑鼠停留看備註，選取後按 Delete 刪除；連動上下軌開啟時，整句落在片段上的字幕會一起刪掉。

## 標記模式的原則

- **不刪任何片段**，只切開、標色、寫備註。
- 採訪者提問的字幕也保留（文字照樣整理），使用者刪片段時會一起刪。
- 片長必須和原始一樣（verify 會檢查）。
- 寧可少標，不要把正常的換氣停頓都標起來：句間停頓 2 秒以上才標，開頭結尾的空白另外判斷。

## 依題目拆段（標記模式的變化）

使用者要「依題目拆分片段、命名註明重點」時（一次錄完的訪談要給後續宣傳片挑金句用）：

- 每題一段 `marks`，給 `name`（例如「Q2 八卦池與動態模型轉成課程」）、`color`、`note`（這題講了什麼、可用的金句與序列秒數）。
- 題目顏色用 `blue`、`green`、`purple`、`lime` 輪替；紅色、橘色保留給建議刪除與長停頓。
- 題目之間的採訪者提問、NG 另外標紅色段，不和題目段重疊（plan 的片段不能重疊）。答到一半的 NG 把題目段拆成前後兩段，兩段用同一個 `name`。
- 題目段已經蓋滿整支時不要開 `autoPauses`，找到的停頓會全部被題目段吃掉。
- 採訪者離麥克風遠，唸題常整段沒辨識出字幕：兩題回答之間「有聲音、沒字幕」的空檔標紅色「訪問者唸 Qn」，備註寫明是推斷。
- 受訪者整題講到一半喊不行、從頭重講：第一次作答整段標紅色 NG，備註寫重講從幾秒開始、第一次有沒有重講版沒有的內容。
- 拆完把專案改成受訪者姓名：`vc.ops(pid, [{"op": "project.update", "patch": {"name": "訪談_姓名"}}])`。
- 同類錯字（地名、設施名）整支都要改，包含 NG 段裡的字幕；export 後用 grep 掃 SRT 確認沒有殘留。

## 重組模式的原則

用在使用者要「讓對話更順」：例如受訪者先講結論再補背景，想把背景移到前面；或採訪者提問與 NG 直接拿掉。

- 不標色，要刪的段落直接刪（`marks`）。
- 移動用 `moves`。移動的單位是完整的句子（`captions` 指定），不要把一句話拆開移動。
- 移動前先確認前後文接得起來：被移走那段的前一句與後一句、移入位置的前一句與被移入段落的第一句，語意都要通。接不起來時寧可不移，在回報裡說明。
- 不跨人物穿插：不把 A 受訪者的話剪進 B 的專案。
- 刪除與移動在同一批 `linked` 操作裡完成，字幕跟著鏡頭移動，使用者按一次 Ctrl+Z 可以整批收回。
- 開頭與結尾的空白用 `marks` 明確指定到 0 秒、片尾。`autoPauses` 遇到片尾的收音雜音會停在雜音前，留下零點幾秒的尾巴。
- verify 加 `--restructure`（片長會變短，不比對片長）。
- 想先試做又不想動到原專案：`POST /api/projects/{pid}/duplicate` 複製一份（回傳 `{"project": {...}}`，鏡頭與字幕代號不變），把工作資料夾的 `transcript.json` 複製一份、`pid` 改成副本的代號再 apply。試完 `vc.delete("/api/projects/<副本>")` 移到垃圾桶。

## 字幕規則

整理文字時遵守（`captions.edit` 由 Claude 寫，空格、標點、拆句由 apply 自動處理）：

1. 去贅詞、精簡串接，**不改寫原意**：句首的「然後」「那」「就是」、重複的「那個」、講到一半改口的前半句可以刪；不加原本沒說的字。
2. 時間碼不得漂移：只改文字，時間由腳本處理（拆句時依字數比例分配，不超出原句範圍）。原始辨識的相鄰兩句常重疊幾毫秒，apply 會自動把前一句結尾截到下一句開頭（只縮不延）。
3. 繁體中文、標準 SRT。
4. 中文與英文、數字之間加空格（apply 自動加）。
5. 一句一行，不出現多行字幕。
6. 每行開頭與結尾不留標點，行中必要的標點保留；ASR 給的空格可當斷句。
7. 每行 18 字以內（空格不算），超過時 apply 自動在標點或空格處拆句；想控制拆點，就在 `captions.edit` 的文字裡放空格。拆句前先算字數：句尾只剩「因此」「然後」「所以」這類兩三字的連接詞把句子推過 18 字時，直接從字幕刪掉（聲音保留，列入 `review.unsure`），不要讓 apply 拆出不到 1 秒、閃一下就消失的短句。
8. 剔除採訪者提問、拍攝倒數、NG 重講、確認口語（標記模式用標色處理，重組模式直接刪）。
9. 同音錯字整理成 `review.corrections` 對照表；有把握才改（例如上下文明確、地名可查證），**不確定的列入 `review.unsure`，不要編造**。人名一律列入待確認。
10. 不跨人物穿插。

## 回報格式

每位受訪者一段：

- 專案名、VC 專案代號、片長、片段數、字幕句數
- 標記（或刪除、移動）清單：時間、顏色、備註
- 字幕修正對照表、待確認清單
- verify 結果

最後一段寫檢查範圍：verify 檢查了什麼、瀏覽器看了哪個專案；**沒驗證到的**：聲音沒聽（判斷依據是字幕內容與音量）、人名與專有名詞未核對、待確認清單上的字。

## 常見問題

| 狀況 | 處理 |
|---|---|
| prepare 卡在語音轉字幕 | `status` 看語音轉字幕是否就緒；第一次載入模型較久。失敗時讀 `<VC>/data/logs/app.log` |
| 轉字幕和轉檔同時跑，兩邊進度都停住 | 顯示卡記憶體小（6GB）時語音辨識和 4K 轉 1080p（`scale`，用 NVDEC／NVENC）會互卡；`remux` 不用顯示卡。不要同時跑：等 transcode.py 全部轉完再 prepare。已經卡住時結束 ffmpeg，轉字幕會繼續，transcode.py 會自動重轉那支 |
| 同一鏡頭轉了兩次字幕，字幕重複 | VC 每轉一次都新增字幕。在 VC 按 Ctrl+Z 收回一批，再用 `--pid` 重跑 prepare 重產逐字稿 |
| apply 說「專案已經分割過」 | 在 VC 復原到分割前，或刪掉專案重新 prepare |
| apply 之後想改 plan 重套 | 復原兩步：`vc.post(f"/api/projects/{pid}/undo")` 呼叫兩次（先收回分割標色，再收回字幕修改），確認只剩 1 個鏡頭、字幕回到原文再 apply。只收回一步就重套，被拆過的長句會再拆一次而重複 |
| verify 報「字幕跨片段」 | 某個切點落在字幕中間：改用 `captions` 指定段落，或把 `start`、`end` 移到字幕空隙 |
| verify 報「時間漂移」 | 某句字幕被移到原始辨識範圍以外（多半是手動拖過）；在 VC 拉回原位 |
| verify 報「字幕重疊」 | 1.3.0 起 apply 會自動截齊原始辨識的重疊。舊版套過的專案：復原兩步再用新版 apply 重套 |
| VC 沒反應 | `vc_client.py` 會在需要時啟動 VC；VC 在沒有視窗也沒有工作 120 秒後自動關閉，腳本執行期間會保持連線 |

## 檔案

| 檔案 | 用途 |
|---|---|
| `scripts/transcode.py` | 攝影機原檔轉成 VC 能匯入的 MP4：每支先判斷保留原畫質或轉 1080p，自動選有聲音的音軌 |
| `scripts/interview_edit.py` | prepare、apply、verify、export |
| `scripts/vc_client.py` | VC API 用戶端（和 `<VC>/tools/vc_client.py` 相同，只用標準庫） |

VC 的完整 API 在 `<VC>/docs/API.md`。使用者要在時間軸上補剪（某個時間點分割、裁剪、定格、分離原聲、倒放、調整一段音量、加關鍵幀）時，用 `vc.timeline(pid)` 找片段位置，再用 `vc.edit(pid, 指令, ...)`，結果和使用者在剪輯頁按快捷鍵相同，一次呼叫是一個復原步驟（API.md 3.7 節）。
